# /pr-review $ARGUMENTS

Проведи ревью изменений тремя Subagents параллельно. Собственных находок при объединении **не** добавляй.

## 1. Определи источник diff

- Если `$0` — номер PR (число), агенты должны получить изменения так: `gh pr diff $0`.
- Если номер не передан (`$ARGUMENTS` пуст), агенты должны использовать: `git diff main...HEAD`.

Сообщи агентам точную команду получения diff в промпте делегирования.

## 2. Запусти трёх агентов параллельно

Делегируй одновременно (одним шагом, параллельно):

1. **bug-hunter** — только логика / null / Promise / race.
2. **performance-reviewer** — только производительность / bundle / лишний `"use client"`.
3. **security-reviewer** — только безопасность / секреты / auth / injection.

Каждому агенту передай:

- команду получения diff (`gh pr diff <N>` или `git diff main...HEAD`);
- указание самостоятельно выполнить эту команду и проанализировать diff;
- запрет редактировать файлы;
- требование вернуть только список проблем в своём формате (или одну фразу, если чисто).

Не передавай агентам чужие отчёты заранее.

## 3. Объедини результаты

После ответов всех трёх:

1. Собери все проблемы в один список.
2. Удали дубликаты (одна и та же проблема в одном файле/строке с тем же смыслом → одна запись; сохрани имена всех агентов, которые её нашли).
3. Сгруппируй по серьёзности: **Critical** → **High** → **Medium** → **Low** (если агент не указал уровень — оцени по описанию, не выдумывая новых багов).
4. У каждой итоговой записи укажи обнаружившего агента (или нескольких).

## 4. Формат итогового отчёта

```markdown
# PR Review

Источник: `gh pr diff <N>` | `git diff main...HEAD`

## Critical
- ...

## High
- ...

## Medium
- ...

## Low
- ...

## Вердикт
...
```

Если в секции нет пунктов — напиши `нет`.

Каждый пункт: `файл:строка — описание — исправление — (агент: …)`.

## 5. Вердикт (обязательно)

В конце одна из формулировок:

- `Вердикт: APPROVE` — нет Critical/High.
- `Вердикт: REQUEST CHANGES` — есть Critical или High.
- `Вердикт: COMMENT` — только Medium/Low.

Не запускай правки кода в рамках этой Skill.
