# /pr-review $ARGUMENTS

Ревью по **Review Policy** из `../doc-plank-fde-training/пайплайн.md`. Набор агентов зависит от Risk Assessment в файле цикла задачи — **не** всегда трое.

Собственных находок при объединении **не** добавляй.

## 0. Risk Assessment и режим

1. Найди файл цикла `../doc-plank-fde-training/циклы/WB-<N>-*.md` для текущей задачи (ветка `feat/WB-<N>`).
2. Прочитай блок `## Risk Assessment` (`Level`, `Review mode`, `Required reviewers`).
3. Если блока нет — сначала выставь Risk Assessment по правилам пайплайна (LOW/MEDIUM/HIGH), запиши в цикл, затем продолжай.

| Level  | Review mode | Кого запускать                                                                                                                                                                                                                        |
| ------ | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LOW    | FAST_TRACK  | Один общий Reviewer: **bug-hunter**. Если diff тривиален и `pnpm check` уже зелёный — можно **не** запускать subagents: вердикт по self-review + CI, в цикле `Agents: none` и причина. Для WB-5…WB-11 предпочтителен один bug-hunter. |
| MEDIUM | STANDARD    | **bug-hunter** + по необходимости **performance-reviewer** и/или **security-reviewer** (если в diff есть perf/security поверхность).                                                                                                  |
| HIGH   | FULL        | Параллельно все трое: **bug-hunter**, **performance-reviewer**, **security-reviewer**.                                                                                                                                                |

После запуска **обязательно** допиши в файл цикла у этапа ревью строку вида:

`Agents: bug-hunter, security-reviewer`  
(или `Agents: none — …`).

## 1. Источник diff

- Если `$0` — номер PR: `gh pr diff $0`.
- Если аргументов нет: `git diff main...HEAD`.

## 2. Контекст агентам (только это)

Каждому запущенному агенту передай:

- acceptance criteria задачикета (кратко);
- список изменённых файлов;
- команду diff и указание выполнить её самому;
- кратко: тесты прошли / нет (без полного лога);
- запрет править файлы;
- **не** анализировать весь репозиторий;
- **не** повторять ESLint, TypeScript, Prettier;
- вернуть только конкретные замечания `файл:строка` или одну фразу, что чисто.

Не передавай чужие отчёты заранее. Незапущенных агентов не вызывай.

## 3. Объединение

1. Собери проблемы в один список.
2. Удали дубликаты (сохрани имена агентов).
3. Группируй: **Critical** → **High** → **Medium** → **Low**.
4. Укажи агента(ов) у каждой записи.

Если агентов не запускали (LOW skip) — вердикт на основе уже известного self-review / check, без выдуманных findings.

## 4. Отчёт

```markdown
# PR Review

Источник: `gh pr diff <N>` | `git diff main...HEAD`
Risk: <LEVEL> · mode: <MODE> · Agents: …

## Critical

- ...

## High

- ...

## Medium

- ...

## Low

- ...

## Вердикт

...
```

Пустая секция — `нет`. Пункт: `файл:строка — описание — исправление — (агент: …)`.

## 5. Вердикт

- `Вердикт: APPROVE` — нет Critical/High.
- `Вердикт: REQUEST CHANGES` — есть Critical или High.
- `Вердикт: COMMENT` — только Medium/Low.

Не запускай правки кода в рамках этой Skill.
